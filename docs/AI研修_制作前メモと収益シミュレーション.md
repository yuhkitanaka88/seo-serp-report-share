## 3. 制作前チェック（プロトタイプ / 要件）

### 3.1 問題ない方針

- **案A**: `/business/ai-training` を横断ハブとして重ね、既存詳細 URL は原則維持
- KW 所有の分離: 総称語（AI研修）／商品・ツール語（生成AI・ChatGPT・Claude）／比較語／属性語
- DX は AI ハブに統合せず `/business/dx` 側
- **クエリURLは作らない**（`?theme=` / `?languages=` 等は正規URLにしない）。通常ファセットは同一ページ内 JS 絞り込みのみ
- 需要と独自内容があるものだけホワイトリストで静的パス化

### 3.1b 研修を探すとディレクトリURL（確定・2026-08-03）

ご指摘どおりの意図:

1. **ナビは「研修を探す」1本**。「AI研修」を並立させない  
2. 一覧で言語・ツール=AIを選ぶとタイトルが **「AI研修を探す」** になる  
3. その条件の正規URLはクエリではなく **ディレクトリ** `/business/ai-training/`

| 画面 | URL | 扱い |
|------|-----|------|
| 研修を探す | `/business/training/` | 唯一の一覧ナビ入口 |
| 同UX・AI条件 | `/business/ai-training/` | AI選択のディレクトリ表現（並立ナビではない） |

ファセット掛け合わせ（AI×オンライン等）は案A幹構造に含めず、ホワイトリスト**候補**として別管理。  
「条件 → ディレクトリURL」はAI以外の言語・ツールにも適用可能で、**インデックスはホワイトリスト承認分のみ**。

UX参考: [Trends 研修検索](https://trends.codecamp.jp/apps/training-search/)

### 3.2 制作前に揃える論点

1. **ファセット掛け合わせLPは幹構造外**

   「AI研修 おすすめ」等はハブと分離する方針だが、専用 URL が未確定。
3. **ハブタイトルの詰め込み**  
   生成AI・ChatGPT・Claude をタイトル主語にすると詳細とカニバリしやすい。ハブは総称語中心が安全。

5. **Claude ページの二層**（全社員活用と Claude Code）は当面 H2 分離でも、主意図を決める。
6. **業務用途詳細のCMSスラッグ**  
   ROUTES.md の候補パスは提案。本番スラッグはCMSに合わせてよい。公開と index を分離すること。

## 4. 獲得〜着金シミュレーション

ダッシュボード操作バー **「7. 着金シミュ」**、または見出し「AI研修 獲得〜着金シミュレーション」。

### 4.1 正しいファネル理解

```text
Organic → KW → 詳細ページ → フォーム → リード → 商談 → 受注（人数） → 着金
```

- 渡されたチャネル表の「CV」は **リード** を意味する（表記をリードに統一済み）
- 着金 = **受注 × 受講人数 × 1名単価**（リード数を直接金額に掛けない）
- 1名単価デフォルト: **150,000円**
- 商談→受注率デフォルト: **10%**
- 受注1件の人数: 多くは **1〜5名**、稀に **20名**（期待値約4.36名／件）。「抽選人数で着金計算」でランダム化

### 4.2 デフォルト CTR

**Organic（順位1〜10）**  
39.8 / 18.7 / 10.2 / 7.2 / 5.1 / 4.4 / 3.0 / 2.1 / 1.9 / 1.6（%）

**LLMO**  
3.9 / 3.68 / 2.79 ＋ 4〜10位は逓減の仮置き（編集可）

### 4.3 件数モード

- **整数（推奨）**: 全体合計してから切り捨て。0.07リードは0件。受注0なら着金 **¥0**（220円のような端数は出さない）
- **期待値（小数）**: 参考用。通常は使わない

行ごとに切り捨てると商談が潰れるため、**合計後に整数化**する。

### 4.4 「抽選人数で着金計算」

受注1件ごとの受講人数を 1〜5（稀に20）でランダムに振る。オフ時は期待人数で安定計算。

### 4.5 なぜサイト全体実績率だと着金が ¥0 に見えるか

チャネル ALL 実績のクリック→リードは約 **0.022%**（ToC/ToB混在の可能性あり。要再確認）。

| 条件 | クリック目安 | リード | 整数受注 | 着金 |
|------|-------------|--------|----------|------|
| 仮置き順位 | ~330 | ~0.07 | 0 | ¥0 |
| 全対象KWを1位 | ~2,500 | ~0.54 | 0 | ¥0 |

この率のまま受注1件にするにはクリックがおおよそ **96万** 必要。対象AI KWの月間SV合計（約 **5,660**）では物理的に足りない。  
→ **順位改善だけでは足りず、リード率改善またはKW母数拡大が必要**、という示唆。

### 4.6 1億円試算ボタン

ボタン名: **「1億円試算（適正値を反映）」**

押下で計画用値を自動反映（サイト全体極小実績ではなく **ToB向け仮置き**）:

| 項目 | 自動反映値 |
|------|------------|
| クリック→リード | 2% |
| リード→商談 | 25% |
| 受注率 | 10% |
| 1名単価 | 150,000円 |
| 目標着金 | 100,000,000円 |
| チャネル | Organic Search |
| 対象KW順位 | 1位想定（上限シナリオ） |

枠内で次を表示:

- 必要受注・商談・リード・クリック（いまの率で逆算）
- 対象AI KWボリュームだけで月次1億円が厳しい場合の明示（上限着金・必要SV倍率など）

解除は **「既定値に戻す」**。

計画率（例: 2% / 25% / 10%）でも、対象AI KWだけの月次着金上限はおおよそ数十万〜百万円規模に留まり、**月次1億円には母数不足**、が現状の示唆。

### 4.7 チャネル実績（/business 配下・2026-07）

サイト全体ではなく **`/business` 配下** に絞った実績を既定値に反映済み。

| チャネル | UU | フォーム到達 | リード（有効CV） | 商談（取引開始） | リード率 |
|----------|-----|--------------|------------------|------------------|----------|
| Organic Search | 188 | 22 | 4 | 0 | 2.13% |
| Paid Search | 904 | 70 | 6 | 1 | 0.66% |
| Direct | 1023 | 91 | 4 | 0 | 0.39% |
| 全体合算 | 2173 | 201 | 17 | 2 | 0.78% |

- 既定チャネル: **Organic Search**（クリック→リード初期値 ≈ 2.13%）
- リード→商談の既定: 全体 **2 / 17 ≈ 11.8%**（Organic 単体は商談0のため）
- 1億円試算ボタンも上記を参考にした推奨値を反映
